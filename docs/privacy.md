# Threadock 隐私声明

> **适用于 v1.0.0** · 最后更新：2026-08-17

## 1. Local-first 承诺

Threadock 的设计前提是：**你的 AI 编程会话历史属于你本人，应当留在你本人的电脑上。**

- 使用 Threadock **不需要注册账号**，没有登录体系；
- **没有遥测**（telemetry）、崩溃上报或使用统计；
- **没有云端组件**：搜索、知识提取、成本计算、安全审计全部在本机完成；
- 数据默认**永不离开本机**——唯一的例外是你主动执行的导出/备份操作，产物也保存在你指定的本地位置。

## 2. 我们不做什么

以下清单是 Threadock 明确**不做**的事：

| # | 我们不做 |
|---|---|
| 1 | 不要求注册、登录或提供邮箱 |
| 2 | 不上传、同步或备份任何数据到我们或第三方的服务器 |
| 3 | 不收集遥测、使用统计、崩溃报告或任何「匿名化」指标 |
| 4 | 不嵌入任何分析 / 广告 / 追踪 SDK |
| 5 | 不在后台连接网络（应用内的外部链接仅在你主动点击时由浏览器打开） |
| 6 | 不读取数据来源目录之外的文件 |
| 7 | 不写入、修改、删除来源 IDE（ZCode / Claude Code / Cursor / MiniMax / Codex）的任何数据 |
| 8 | 不代你执行命令或自动化任务（治理中的自动化清单为只读展示） |
| 9 | 不存储你的备份密码，也没有任何密码找回后门 |

## 3. 我们读取什么：数据采集范围

为建立统一会话库，Threadock 会**只读**扫描以下本机目录（均为各 AI 工具自身存放会话历史的位置）：

| 来源 | 读取位置（以 macOS 为例） | 形式 |
|---|---|---|
| ZCode | `~/.zcode/cli/db/db.sqlite` | SQLite 数据库 |
| Claude Code | `~/.claude/projects/` 下的 `.jsonl` 文件 | JSONL 会话文件 |
| Cursor | `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` | SQLite 数据库 |
| MiniMax Code | `~/.minimax/v2/sqlite/runtime-state.sqlite` | SQLite 数据库 |
| Codex | `~/.codex/sessions/` 下的 `.jsonl` 文件 | JSONL 会话文件 |

读取的内容包括：会话元信息、用户消息与助手回复、工具调用记录、命令、代码 Diff、产物（Artifact），以及用于治理视图的请求级用量指标（Token 数、模型、耗时等）。治理中的资产盘点还会读取各 Agent 已安装的 skills / plugins 清单与定时任务配置（同样只读）。

**只读快照原则**：Threadock 以只读方式打开上述数据库与文件，将内容复制（快照）到自己的库中后立即关闭，不持有任何写句柄。上述目录之外的个人文件不会被扫描。

你也可以手动导入任意 Markdown / JSONL 文件，此类导入仅读取你明确选择的文件。

## 4. 数据存储在哪里、如何保护

所有数据存放在本机的应用数据目录：

| 系统 | 数据目录 |
|---|---|
| macOS | `~/Library/Application Support/com.threadock.desktop/` |
| Windows | `C:\Users\<用户名>\AppData\Roaming\com.threadock.desktop\` |
| Linux | `~/.local/share/com.threadock.desktop/` |

目录内各组件及保护措施：

| 组件 | 内容 | 保护措施 |
|---|---|---|
| `threadock.db` | 主数据库（会话、消息、知识、治理指标等） | SQLite WAL 模式；存储于用户数据目录，遵循操作系统的用户权限 |
| `raw/` | 原始会话归档（未经加工的源数据副本） | **BLAKE3** 内容寻址（任何篡改可被检测）+ **zstd** 压缩；内容去重 |
| 搜索索引 | 全文检索索引（Tantivy） | 仅含索引数据，可随时删除并从主库重建 |
| `reports/` | 周报与审计报告（HTML） | 仅本地生成与保存 |

**备份加密**：你创建的备份文件（`.chbak`）使用 **XChaCha20-Poly1305** 认证加密；加密密钥由你设置的密码经 **Argon2id** 密钥派生算法计算（每次备份使用随机 16 字节盐）。密码不落盘、不缓存，仅在备份/恢复进行中在内存里使用。忘记密码即无法解密对应备份——这是设计使然，不存在后门。

数据在磁盘上未做整库透明加密（如 FileVault / BitLocker 之外的额外加密），数据库保护等同于你操作系统用户账户的保护级别。对数据保密性有更高要求时，建议开启操作系统级磁盘加密。

## 5. 脱敏与导出

导出会话或知识时，Threadock 自动对导出内容执行**脱敏**，内置覆盖 12 类敏感信息（AWS 密钥、GitHub / Slack / GitLab / Google Token、`sk-` 系列 API Key、Bearer Token、JWT、PEM 私钥块、邮箱、私有 IP 等），命中内容替换为 `[REDACTED:类型]` 占位符，并附命中统计供核对。

- 你可以添加**自定义脱敏规则**（正则表达式），覆盖项目特有的敏感格式；
- 脱敏只作用于导出的副本，Threadock 本地库中的原始内容保持不变，以便你随时完整回溯；
- **导出后的文件完全由你掌控**：Threadock 不会替你发送、上传导出结果，请自行谨慎分享。

## 6. 治理数据（用量 / 成本指标）同样仅本地

治理视图使用的 Token 用量、成本估算、模型调用统计、健康评分、审计发现等指标，全部从本地会话数据计算得出，**仅存储在本地数据库中**。其中：

- 成本为基于可编辑的本地定价表（`pricing.json`）的估算值，不与任何计费服务通信；
- 周报与审计报告为本地 HTML 文件，保存在数据目录的 `reports/` 下，是否分发由你决定。

## 7. 第三方数据的边界：只读，不写入

「对第三方数据只读、不修改源库」是 Threadock 的核心设计约束之一：

- Threadock 对来源 IDE 的数据库与文件**只读取、不写入**——不存在任何修改、清理或「优化」源 IDE 数据的功能；
- 你在 Threadock 中执行的收藏、标签、归档、删除，仅作用于 Threadock 自己的副本库；
- 各数据来源的解析工作在**相互隔离的独立进程**中完成，即使某一来源的数据异常，也不会影响来源工具本身或其他来源的导入；
- 卸载 Threadock 不会在来源工具中留下任何痕迹。

## 8. 删除你的数据

你对自己的数据拥有完全控制权，可随时：

- **单条清理**：会话先软删除进回收站，可恢复；「彻底删除」会连同其原始归档与搜索索引一并级联清除；
- **按时间重置**：删除某日期之后的全部本地数据（会自动从源 IDE 重新拉取）；
- **全部清除**：设置中的重置功能可清空 Threadock 库；删除应用数据目录则连同所有历史、偏好与报告一并清除。

以上操作均不影响来源 IDE 中的原始数据。

## 9. 免责声明

- Threadock 按「现状」提供，不对其适销性、特定用途适用性作任何担保；
- 你导入、导出、备份的数据内容由你本人负责。导出含敏感信息的文件、向他人透露备份密码等行为的风险由使用者承担；
- 成本、用量等治理指标为本地估算值，可能与供应商账单存在差异，仅供参考；
- 请遵守你所使用的各 AI 工具的服务条款及适用法律，勿使用 Threadock 处理你不有权处理的数据。

## 1. Threadock 是什么

Threadock 是一个**运行在你自己电脑上**的跨 AI IDE 会话管理平台。如果你同时在用 ZCode、Claude Code、Cursor、MiniMax Code、Codex 等工具写代码，每个工具都会各自留下一份会话历史——Threadock 把这些分散的会话、工具调用、命令、代码 Diff 与产物**只读地**收集到本地一个统一库里，然后提供：

- **统一检索**：跨全部工具的全文搜索（支持中文），不用再逐个工具翻历史；
- **知识沉淀**：从会话中自动提取摘要、决策、TODO、错误、命令、文件六类知识，形成可复用的知识库；
- **用量治理**：统计 Token 与成本、设置预算告警、扫描安全隐患、管理存储与保留策略。

所有数据默认完全留在本机，无账号、无遥测、不上传。详见[隐私声明](./privacy.md)。

## 2. 安装与首次启动

### 2.1 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | macOS、Windows 或 Linux（64 位） |
| 内存 | 建议 4 GB 以上 |
| 磁盘 | 视历史会话量，通常几百 MB 起步 |
| 前置条件 | 无。至少安装了一个受支持的 AI IDE 才有数据可导入 |

### 2.2 安装

从 [GitHub Releases](https://github.com/sunqingguang/threadock/releases) 下载对应平台的安装包：

| 平台 | 安装包 |
|---|---|
| macOS | `.dmg`（拖入 Applications） |
| Windows | `.msi` |
| Linux | `.AppImage`（赋予执行权限后运行） |

> **关于签名**：v1.0.0 安装包未购买开发者证书做签名/公证。macOS 首次打开若被 Gatekeeper 拦截，请在「系统设置 → 隐私与安全性」中点击「仍要打开」；Windows SmartScreen 提示时选择「仍要运行」。后续版本会补充正式签名。

### 2.3 首次启动与新手引导

首次启动会自动出现**新手引导**（共 6 步），依次介绍：

1. 导入 AI 工具的历史会话；
2. 命令面板（`⌘K` / `Ctrl+K`）：搜索会话、按关键字跳页、运行操作；
3. 各视图的功能分工（`⌘1`..`⌘8` 快速切换）；
4. 知识提取：把会话沉淀为知识库；
5. 安全审计与一键处置；
6. 设置：偏好、备份与关于。

引导内容会根据库中是否已有数据自动区分（空库侧重导入，老库侧重检索回顾）。随时可在 **设置 → 新手引导** 重新查看。

## 3. 界面总览：七大视图

Threadock 按功能分为七个视图。侧边栏上有八个导航入口（`⌘1`..`⌘8`），其中「成本 / 安全 / 资产」三个入口同属治理域：

| 视图 | 侧边栏入口 | 一句话说明 |
|---|---|---|
| 概览 | 📊 概览 | 全库关键指标与趋势的仪表盘 |
| 会话 | 💬 对话 | 浏览、搜索、整理所有导入的会话（核心视图） |
| 知识 | 📚 知识库 | 从会话提取的六类知识与高频命令/文件 |
| 活动 | 📆 活动 | GitHub 风格热力图，看你的 AI 使用节奏 |
| 项目 | 📁 项目 | 按项目（工作区）聚合的会话与成本 |
| 治理 | 💰 成本 / 🛡 安全 / 🧩 资产 | 预算、审计、资产盘点与自动化观察 |
| 设置 | 右上角 ⚙ | 外观、同步、备份、存储维护等全局配置 |

顶部为全局搜索与导入入口，底部状态栏显示同步状态。任意页面按 `⌘K` / `Ctrl+K` 可唤起命令面板快速跳转。

## 4. 视图详解

### 4.1 概览

概览是打开后的仪表盘，包含：

- **关键指标卡片**：会话数、消息数、最近活动、新增会话数（可点击跳转到对应视图；每张卡片可单独隐藏）；
- **最近会话与最近提问**：快速回到最近的工作上下文；
- **来源分布**：五个 IDE 来源各自的会话占比。

### 4.2 会话

会话视图是日常使用最多的地方，由**左侧会话列表**与**右侧详情**组成。

**会话列表**

- 顶部搜索框支持全文搜索与查询语法（见[第 6 章](#6-搜索技巧)）；
- 来源筛选：导入后出现按工具（ZCode / Claude Code / Cursor / MiniMax / Codex）的筛选标签；
- 四个列表维度：**全部 / 收藏 / 已归档 / 回收站**；
- 每条会话显示标题、来源、时间与完整度标签。

**右键菜单与批量操作**

- 右键任意会话：收藏 / 取消收藏、加标签、归档 / 取消归档、删除（进回收站）；
- `⌘` 点击（Windows/Linux 为 `Ctrl` 点击）多选，`⌘A` 全选；
- 选中多条后可批量：收藏、归档、删除、加标签。

**回收站**

- 「删除」是软删除：会话进入回收站，可随时**恢复**；
- 「彻底删除」为硬删除：需输入「删除」二字确认，永久移除会话及其原始归档、搜索索引与治理记录（级联清理，不可恢复）。

**会话详情**

- **时间线**：用户消息、助手回复、工具调用、命令、Diff、产物等按时间戳合并展示；
- **子任务**：Agent 派生的子会话按父子关系挂在主会话下；
- **私人笔记**：给会话添加自己的备注，仅存于 Threadock；
- **相似会话**：基于内容推荐历史相近的会话；
- **知识提取与导出**入口：见[第 7 章](#7-知识提取与导出含脱敏)。

## 5. 数据来源与自动同步

### 5.1 五个数据来源（只读）

Threadock 目前支持从以下五个 AI IDE 导入会话，**全部只读**：

| 来源 | 读取位置（以 macOS 为例） | 形式 |
|---|---|---|
| ZCode | `~/.zcode/cli/db/db.sqlite` | SQLite 数据库 |
| Claude Code | `~/.claude/projects/` 下的 `.jsonl` 文件 | JSONL 会话文件 |
| Cursor | `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` | SQLite 数据库 |
| MiniMax Code | `~/.minimax/v2/sqlite/runtime-state.sqlite` | SQLite 数据库 |
| Codex | `~/.codex/sessions/` 下的 `.jsonl` 文件 | JSONL 会话文件 |

只要本机安装过对应工具，Threadock 就能自动发现其数据；未安装的来源会被自动跳过。

此外还支持**手动导入通用文件**：在「导入」菜单中选择任意 Markdown / JSONL 会话文件，并指定归属的工作区名称。

### 5.2 只读原则

Threadock 对来源 IDE 的数据库和文件**只做读取，从不写入或修改**。所有在 Threadock 里的收藏、标签、删除等操作只作用于 Threadock 自己的数据库，源 IDE 完全不受影响——卸载 Threadock 也不会给它们留下任何痕迹。

### 5.3 自动同步与增量导入

- 首次导入：点击左上角「导入 → 增量同步」，Threadock 会读取全部来源的历史会话；
- 之后每 **10 分钟**自动执行一次增量同步（间隔可在设置中调整为 5 / 10 / 30 分钟或关闭），同步过程可随时取消；
- **增量机制**：Threadock 记录每个来源的同步进度，只重新读取有更新的会话；内容未变化的会话通过内容哈希直接跳过，因此日常同步很快；
- 用量指标（用于治理视图）另有 30 分钟的采集节流，可在设置中手动强制刷新。

## 6. 搜索技巧

### 6.1 纯文本搜索

直接在搜索框输入关键词即可，支持中英文混合、多词组合，结果按相关度排序并**高亮命中片段**。中文无需分词空格，逐字可搜（基于 N-gram 索引）。

示例：`后台任务`、`WorkManager`、`rust 编译错误`。

### 6.2 查询语法（v1.0.0 新增）

v1.0.0 支持在关键词前后叠加过滤条件，格式为 `字段:值`，多个条件可组合使用：

| 语法 | 作用 | 示例 |
|---|---|---|
| `provider:` | 按来源工具过滤 | `provider:cursor`、`provider:claude_code` |
| `workspace:` | 按工作区（项目）过滤 | `workspace:my-web-app` |
| `type:` | 按内容类型过滤 | `type:tool_call`（只搜工具调用），其他常用值：`command`、`diff`、`artifact` |
| `file:` | 按涉及的文件路径过滤 | `file:src/main.rs` |
| `status:` | 按会话状态过滤 | `status:favorite`（收藏）、`status:archived`（已归档）、`status:deleted`（回收站） |
| `after:` | 只搜某日期之后 | `after:2026-08-01` |
| `before:` | 只搜某日期之前 | `before:2026-08-15` |
| `model:` | 按模型过滤 | `model:gpt-5` |

组合示例：

```text
provider:cursor 修复类型错误              # Cursor 会话中搜「修复类型错误」
workspace:my-app after:2026-07-01 deploy  # 某项目 7 月以后关于 deploy 的会话
type:tool_call file:package.json          # 涉及 package.json 的工具调用
```

提示：值中含空格时用引号包裹，如 `workspace:"my web app"`。

### 6.3 保存搜索

经常使用的查询条件可以**保存为常用搜索**：输入查询后点击搜索框旁的「保存」，为其命名，之后从已保存列表一键复用，无需重复输入。保存的搜索会随偏好配置一起备份/迁移（见设置 → 配置导入/导出）。

## 7. 知识提取与导出（含脱敏）

### 7.1 提取知识

- **单会话**：打开会话详情，通过命令面板（`⌘K`）或详情页按钮执行「提取知识」，得到摘要 / 决策 / TODO / 错误 / 命令 / 文件六类结果，可保存进知识库（多次提取保留版本）；
- **批量**：知识库视图提供「批量提取」，对全部未提取的会话一次跑完。

默认提取基于内置**规则引擎**在本地完成，不调用任何外部服务。规则引擎确定性、离线、零成本，是所有场景的默认兜底。

### 7.2 AI 提取（大模型，可选）

知识提取支持切换到**大模型引擎**：把当前会话的对话文本发送给你配置的模型，按同一套六类结构返回更高质量的纪要（`摘要/决策/TODO/错误/命令/文件` + 消息级来源引用）。

**开启步骤**（设置 → AI 提取（大模型））：

1. 勾选「启用大模型提取」（默认关闭，规则引擎不受影响）；
2. 填写 OpenAI 兼容端点与模型名，或点击预设快捷填入：

   | 预设 | Base URL | 模型示例 | 形态 |
   |---|---|---|---|
   | OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 云端 |
   | DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 云端 |
   | GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 云端 |
   | Ollama 本地 | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | **本地推理，数据不出本机** |

   任何 OpenAI 兼容服务（LM Studio、llama.cpp server、vLLM 等）都可以，本地服务地址会被识别并标记「本地」徽标（允许 http）；
3. 云端端点填入 API Key（本地推理可留空），点「测试连接」验证；
4. 在任意会话的「知识提取」弹窗用 ⚙规则 / ✨AI 段选切换引擎（切换即重新提取），结果中会标注所用模型（`llm:{model}@prompt-v1`）。

**API Key 的本地安全**：

- Key 以 **XChaCha20-Poly1305** 认证加密后存入本地数据库（密文形态，每次随机 nonce）；
- 加密主密钥保存在**操作系统钥匙串**（macOS Keychain / Windows Credential Manager / Linux Secret Service）；无钥匙串环境自动回退为应用数据目录下 **0600 权限**的密钥文件（可用环境变量 `THREADOCK_NO_KEYCHAIN=1` 强制走文件）；
- 明文 Key 永不落盘、不出现在日志与错误信息；界面只显示打码形态（如 `sk-***1234`）；
- 数据库被单独拷走/泄露时，没有主密钥无法解出 Key；
- 非本地端点强制 https（拒绝云端明文 http，防凭据裸奔）。

**隐私边界**：开启 AI 提取后，仅在你主动触发提取时，把**当前会话**的对话文本（超过上限自动截断，默认 48,000 字符）发送到所配端点；本地推理端点数据不出本机。详见[隐私声明](./privacy.md)。

### 7.3 导出

会话与知识均可导出为本地文件：

- **单会话**：Markdown（`.md`）或 JSON（`.json`）；
- **整个工作区**：通过 CLI 一次导出该工作区下全部会话（见 `ch export workspace`）。

### 7.4 脱敏选项

导出时 Threadock 会**自动脱敏**命中的敏感信息，替换为 `[REDACTED:类型]` 占位符（保留可读结构、去除敏感值），并在导出结果中统计命中次数便于核对。内置覆盖 12 类：

| 类别 | 示例 |
|---|---|
| AWS Access / Secret Key | `AKIA...` |
| GitHub Token | `ghp_` / `gho_` 等 |
| API Key | `sk-`（含 `sk-proj-` / `sk-ant-`）、`api_key=...` |
| Bearer Token | `Bearer xxx` |
| Slack / GitLab / Google Token | `xoxb-`、`glpat-`、`AIza...` |
| JWT | 三段式 `eyJ...` |
| PEM 私钥块 | `-----BEGIN ... PRIVATE KEY-----` |
| 邮箱地址 | `someone@example.com` |
| 私有 IP | `10.*` / `172.16-31.*` / `192.168.*` |

**自定义规则**：项目特有的敏感格式（如内部密钥前缀）可在治理 → 安全的脱敏规则管理中添加，或用 CLI：

```bash
ch --db <库路径> redaction-rule add my-key 'sk-foo-[0-9]+'
ch --db <库路径> redaction-rule list
```

> 注意：脱敏只作用于**导出的副本**；Threadock 本地库中的原始内容不变。导出文件由你自行保管，请仅分享给需要的人。

## 8. 备份与恢复

### 8.1 创建备份（GUI）

**设置 → 加密备份**：

1. 输入备份密码（至少 8 位）；
2. 点击「备份全部数据」，选择保存位置（默认文件名 `threadock-backup-日期.chbak`）；
3. 备份包含数据库与全部原始归档。

### 8.2 加密方式

- 备份文件使用 **XChaCha20-Poly1305** 认证加密；
- 加密密钥由你的密码经 **Argon2id** 密钥派生函数计算而来，每次备份使用随机 16 字节盐；
- 密码不存储在任何地方，进程内用完即弃，**没有找回通道**——忘记密码将无法恢复该备份，请妥善保管。

### 8.3 恢复

恢复通过 CLI 完成（恢复到指定目录，生成数据副本，不影响当前使用中的数据）：

```bash
CH_BACKUP_PASSWORD="你的备份密码" ch --db <库路径> restore hub.chbak restored/
```

之后可将 `restored/` 目录内容替换到 Threadock 数据目录完成迁移（数据目录位置见 [FAQ](#11-常见问题faq)）。

## 9. 治理功能详解

### 9.1 预算告警

在治理 → 成本页设置**月度预算**：

- 可分别设置每月 Token 上限与成本（美元）上限；
- 顶部常驻**预算条**实时显示本月用量占比；
- 超出预算时弹出应用内告警（每月仅提醒一次，避免打扰），可在设置中关闭；
- **月末预测**：按最近日均消耗外推到月底，提前看出是否会超。

### 9.2 安全审计

治理 → 安全页：

- **全库扫描**：检查所有已导入会话中的敏感信息泄露与危险命令（如删库、强制推送、危险路径写入）；
- **风险调用列表**：按时间列出命中的具体调用，可展开查看上下文，点击可跳回原会话；
- **处置**：单条或批量「忽略 / 标记为误报」，处置结果持久保存，重复扫描不再打扰；
- **策略规则**：自定义危险命令黑名单（正则），支持启用/停用，可导出 JSON 在其他机器导入；
- **报告**：一键导出 HTML 审计报告；
- **异常检测**：自动识别错误尖峰、重试风暴、上下文超限等异常模式。

### 9.3 保留策略

设置 → 存储与维护 → 保留策略：可选择关闭 / 30 天 / 90 天 / 180 天。开启后，每次启动自动把**超过 N 天未更新**的会话归档（不是删除），归档的会话仍在「已归档」视图中可查、可取消归档。

### 9.4 存储管理（GC）

设置 → 存储与维护：

- **存储看板**：数据库、原始归档、搜索索引三者的体积一览；
- **孤儿数据清理（GC）**：扫描并删除不再被任何会话引用的原始归档文件，释放磁盘空间（带并发保护，不会误删正在写入的数据）；
- **重建搜索索引**：搜索结果异常（如刚从旧版本升级）时可用于修复；
- 所有清理动作记入治理操作流水。

### 9.5 周报

- 超过 7 天未生成周报时，启动后自动生成一份 HTML 周报（保存在本地数据目录的 `reports/` 下）；
- 也可在概览页或设置中手动「立即生成」，HTML 可导出到任意位置；
- 概览页的「报告中心」可回看全部历史周报。

### 9.6 治理资产（skills / 自动化）

- **资产盘点**：列出各 Agent 已安装的 skills 与 plugins，跨工具统一查看；
- **自动化观察清单**：汇总各工具配置的定时/自动化任务，**只读展示**——Threadock 不会代你执行或修改任何自动化任务。

## 10. 命令行工具 `ch` 简表

随桌面应用一同提供命令行工具 `ch`，适合脚本化操作。多数命令需用 `--db` 指定数据库路径（桌面版数据库位置见 FAQ）。

| 命令 | 作用 |
|---|---|
| `ch --db <db> import <文件> --workspace <名称>` | 导入 Markdown / JSONL 会话文件 |
| `ch --db <db> import-from <来源> list` | 列出某来源（如 `claude-code`、`zcode`）可导入的会话 |
| `ch --db <db> import-from <来源> <会话ID>` | 从来源 IDE 只读导入指定会话 |
| `ch --db <db> list [--favorite] [--provider codex]` | 列出会话（可按收藏 / 来源过滤） |
| `ch --db <db> search <关键词>` | 全文搜索 |
| `ch --db <db> search-tantivy <关键词>` | 指定 Tantivy 引擎搜索 |
| `ch --db <db> favorite <id>` / `unfavorite` / `favorites` | 收藏管理 |
| `ch --db <db> tag <id> <标签>` / `untag` / `tags` | 标签管理 |
| `ch --db <db> archive <id>` / `unarchive` | 归档管理 |
| `ch --db <db> delete <id>` | 软删除（`undelete` 可恢复） |
| `ch --db <db> delete <id> --hard` | 硬删除（永久，级联清理） |
| `ch --db <db> knowledge <id> [--save] [--show]` | 知识提取 / 保存 / 查看 |
| `ch --db <db> similar <id>` | 相似会话推荐 |
| `ch --db <db> export markdown <id> <输出.md>` | 导出 Markdown |
| `ch --db <db> export json <id> <输出.json>` | 导出 JSON |
| `ch --db <db> export workspace <工作区ID> <目录>/` | 批量导出整个工作区 |
| `ch --db <db> redaction-rule add <名称> <正则>` / `list` | 自定义脱敏规则 |
| `CH_BACKUP_PASSWORD=密码 ch --db <db> backup <文件>.chbak` | 创建加密备份 |
| `CH_BACKUP_PASSWORD=密码 ch --db <db> restore <文件>.chbak <目录>/` | 恢复备份 |
| `ch --db <db> daemon` | 启动本地 JSON-RPC 常驻服务（进阶） |
| `ch --db <db> integrity` | 数据库完整性检查 |

## 11. 常见问题（FAQ）

**Q1：我的数据保存在哪里？**

全部在本机应用数据目录中：

| 系统 | 数据目录 |
|---|---|
| macOS | `~/Library/Application Support/com.threadock.desktop/` |
| Windows | `C:\Users\<用户名>\AppData\Roaming\com.threadock.desktop\` |
| Linux | `~/.local/share/com.threadock.desktop/` |

目录内包含：`threadock.db`（主数据库）、`raw/`（原始归档）、`reports/`（周报）、`pricing.json`（模型定价）。

**Q2：卸载 Threadock 会影响我源 IDE（Cursor / Claude Code 等）的数据吗？**

**不会。** Threadock 对来源工具只读，从不写入；收藏、标签、删除等操作只发生在 Threadock 自己的数据库里。卸载 Threadock 只需删除应用；若想连同历史数据一并清除，再手动删除上面的数据目录即可。

**Q3：数据会上传到云端吗？**

不会。Threadock 没有账号体系、没有遥测、不连接任何云端服务，所有功能（含成本计算、安全审计、知识提取）均在本地完成。详见[隐私声明](./privacy.md)。

**Q4：删除的会话去哪了？如何彻底删除？**

先进入「回收站」（软删除），可随时恢复；在回收站中执行「彻底删除」并输入「删除」确认后才会永久移除，同时清理其原始归档与索引。按时间批量清理可用设置中的「按时间重置」。

**Q5：为什么某个来源是空的？**

可能原因：该工具在本机没有历史数据；首次导入尚未完成（等待或手动点「增量同步」）；该来源的会话全部处于隐藏状态（如 MiniMax 的隐藏会话默认不导入）。

**Q6：搜索结果看起来不全或中文搜不到？**

尝试设置 → 存储与维护 →「重建搜索索引」。

**Q7：忘记备份密码怎么办？**

无法找回。备份使用 Argon2id 从密码派生密钥，没有任何后门或恢复通道。

**Q8：如何把数据迁移到新电脑？**

旧电脑：设置 → 加密备份，生成 `.chbak` 文件；新电脑：安装 Threadock，用 `ch restore` 恢复到数据目录（见第 8 章）。偏好类配置（主题、收藏、保存的搜索等）可用设置中的「导出/导入配置」单独迁移。

**Q9：自动同步会拖慢我的电脑吗？**

日常增量同步只读取有变化的会话，占用很小；同步在后台执行且可随时取消。如仍不希望后台活动，可在设置中关闭自动同步，改为手动触发。
